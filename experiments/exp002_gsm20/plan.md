# exp002 · GSM8K 上的 Self-Refine

## 要复现的那个数字

GSM8K（论文里叫 Math Reasoning）上，**一次生成（attempt 0）vs 4 轮精化后（attempt 4）的 solve rate**。

## 论文值（Table 1）

| 基座模型 | Base | +Self-Refine |
|---|---|---|
| GPT-3.5 | 64.1 | 64.1 |
| ChatGPT | 74.8 | 75.0 |
| GPT-4 | 92.9 | 93.1 |

论文 §5 另有一组（GPT-3，对比 Self-Correction）：45.9 → 55.7。

## 论文自己给的规律

基座模型越强，提升空间越小：GPT-4 已经 92.9%，只提 0.2 个点；GPT-3 只有 45.9%，提了 9.8 个点。

## 另一个参考：官方数据的结果

用官方发布的结果文件（前 20 题）跑了一遍评测脚本：

- attempt 0 = 14/20 = 70%
- attempt 4 = 14/20 = 70%

**零提升。**

## 我的预测（跑之前写的）

| | 预测 |
|---|---|
| attempt 0 | 80%（16/20） |
| attempt 4 | 85%（17/20） |
| 提升幅度 | +1 题 |

**我这么猜的理由**：

1. 论文的规律是"基座越强、提升越小"。deepseek-v4.1-flash 是现代模型，GSM8K 大概率在 80% 上下，提升空间不大。
2. 官方数据在同样这 20 题上是零提升，说明这个任务本身就很难改对。
3. 但完全零提升也太绝对，我猜会多对 1 题。

## 已知风险

1. **20 题的分辨率是 5%/题** —— ±1 题以内的差异不能当结论（任务书 6.1 第 4 条）。
2. `src/gsm/run.py:70-72` 有 `except: pass`，会静默吞掉失败的题 → 跑完必须 `wc -l` 数行数，必须是 20 行。
3. 评测脚本分母写死 1319，20 题时必须自己按 `len(df)` 重算。
4. 模型是思考型 + prompt 被改过（加了 `system_message`），和论文不可直接比。
